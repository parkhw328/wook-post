# wPost 0.1.0 점검 기록

## 범위와 판단

2026-10-08 요청에 따라 화면 가독성, 요청·응답, 저장·복원, 백업, 환경·인증, 데이터 표시를 점검했다. Electron 메인·preload·renderer와 공유 스키마, HTTP·SQLite·파일 변환 코드를 확인하고 실제 로컬 서버와 Electron 창으로 검증했다.

기능 문제 3건을 재현해 수정했다. 수정 후 확인한 주요 기능에서 추가 오류는 발견하지 않았다. 이는 아래 범위의 결과이며 모든 외부 API나 모든 Windows 환경의 동작을 보증하는 의미는 아니다.

## 재현한 문제와 수정

| 문제               | 수정 전 증상                                                                                          | 수정 및 검증                                                                                                                                  |
| ------------------ | ----------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 응답 복사          | 복사 버튼을 누르면 `Write permission denied`                                                          | 저장된 응답 ID를 검사하는 제한된 IPC로 메인 프로세스에서 복사. 실제 클립보드 값과 원본 응답이 같은지 E2E로 확인                               |
| JSON 값 변경       | `9007199254740993`이 Pretty 화면에서 `9007199254740992`로 표시됨. 요청 본문 정렬도 동일한 변환을 사용 | 객체 재직렬화를 제거하고 토큰을 보존. 큰 정수·소수의 끝자리·지수·음의 0·중복 키·이스케이프·한글을 확인. 정렬한 요청의 실제 전송 바이트도 확인 |
| 히스토리 중복 표시 | 100건 상태에서 더 보기를 연속 클릭하면 200건 대신 300개 행이 표시됨                                   | 진행 중 중복 호출 방지, 변경된 목록에 늦게 도착한 페이지를 추가하지 않도록 처리. 210건 백업으로 재현 테스트 후 200개 고유 행 표시 확인        |

응답 원본 바이트의 저장·내보내기는 기존에도 유지됐다. JSON 문제는 표시 및 요청 편집기의 정렬에 영향을 주었다.

## 가독성

- 앱·설치 파일 버전은 `0.1.0`. ALPHA 배지와 초기 알파 안내 제거.
- JetBrains Mono Regular/Bold와 Noto Sans KR 가변 글꼴을 앱에 포함. Chromium이 실제로 영문에 JetBrains Mono, 한글에 Noto Sans KR 번들 글꼴을 사용하는지 확인.
- 일반 UI 16px, URL·요청 본문·응답 코드·응답 헤더 17px, 보조 정보 최소 14px. 작은 창에서도 본문 크기 유지.
- 보조 텍스트 대비, 클릭 영역, OPTIONS 메서드 선택 너비, 환경 설정창, 요청·응답 공간과 스크롤 조정.
- 응답 `code` 요소의 브라우저 기본 글꼴 재정의를 제거하고 공통 글꼴 상속.
- 1440×940 및 1000×700에서 실제 화면 확인. 최소 창의 응답 영역은 세로 스크롤로 전체 본문을 읽을 수 있으며 요청 영역 높이는 드래그로 조절 가능.

## 확인한 동작

- 요청: 중복 쿼리·헤더, JSON·폼, 환경 변수, Bearer/Basic 인증, HEAD, HTTP 오류 응답.
- 통신: 타임아웃, 취소, 리다이렉트 설정, 다른 origin으로 이동할 때 인증 정보 제거, 응답 크기 한도와 부분 저장 표시.
- 저장: 컬렉션·환경·요청·히스토리 재시작 복원, 100건 단위 조회, 잘못된 가져오기 전체 롤백.
- 파일: 기존 스키마 v1 백업, Postman 지원 형식, 중복 히스토리 방지, 바이너리 바이트 보존, 원자적 파일 교체.
- UI: 저장·전송 단축키, 저장하지 않은 상태의 종료 확인, 복사, JSON 정렬, 한글 글꼴, 작은 창, 라이선스 열람.

자동화 명령: `npm run check`, `xvfb-run -a npm run test:e2e`. 타입·포맷 검사, 단위·통합 테스트 **28개**, Electron E2E 시나리오 **5개**가 모두 통과했다.

## 남은 확인 범위

- 이 환경은 Linux이다. Windows 실제 설치·업그레이드·제거와 125%·150% 디스플레이 배율은 Windows에서 확인해야 한다. 코드 서명은 아직 구성하지 않았다.
- 기존 미지원 기능: multipart 파일 전송, OAuth 2.0, 쿠키 자동 관리, 사용자 지정 프록시·클라이언트 인증서, 스크립트·컬렉션 실행기.
- 기존 저장 범위: 로컬 DB와 백업은 평문이며 요청 1 MiB, 응답 5 MiB, 백업 100 MiB 한도를 유지한다.

설치 파일과 패키지 확인 결과는 [0.1.0 Windows 빌드 기록](../builds/v0.1.0-windows.md)에 기록한다.

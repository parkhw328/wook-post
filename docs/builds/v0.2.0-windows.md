## 이번 빌드

wShell과 구분되는 파란색 P 아이콘, 컬렉션 이름 변경·삭제, 영문·한글 글꼴 및 전체 글자 크기 80–150% 설정을 포함한다. 요청을 보존하는 컬렉션 삭제가 기본이며 열린 편집 내용과 히스토리를 유지한다. 화면 설정은 미리보기·취소·기본값 복원·저장 후 재실행을 지원한다. [기능 점검](../reviews/v0.2.0.md)과 [변경 이력](../../CHANGELOG.md)을 참고한다.

설치 `appId: com.parkhw328.wookpost`, 사용자 데이터 위치 `%APPDATA%/Wook Post/wook-post.sqlite`, 백업 스키마 v1은 유지한다. 기존 SQLite에 화면 설정 테이블만 추가한다. 이전 설치 파일과 태그는 보존한다.

## 환경과 검증

Rocky Linux 로컬 환경에서 번들을 생성하고 고정 Docker 이미지의 Node.js 24.15.0 / Wine 11.0으로 Windows x64 NSIS 패키지를 만들었다. Electron 44.7.0, electron-builder 26.15.3, NSIS 3.0.4.1을 사용했다.

- `npm run check`: TypeScript·Prettier·단위/통합 테스트 **35개 통과**.
- `xvfb-run -a -s '-screen 0 1600x1000x24' npm run test:e2e`: 실제 Electron 시나리오 **8개 통과**.
- 기본 1440×940 및 최소 1000×700 창에서 확인했다. 설정 미리보기·취소·재실행과 150% 글자 크기의 실제 요청 전송을 검증했다.
- 7-Zip NSIS 무결성 검사: `Everything is Ok`.
- 앱·설치기 각각의 아이콘 리소스에 새 PNG 이미지 7종(16·24·32·48·64·128·256px)이 ICO 원본과 같은 해시로 포함됨을 확인했다. 별도 창 아이콘 PNG도 소스와 일치한다.
- `wPost.exe`는 x86-64 PE. 설치 부트스트랩 자체는 PE32이다.
- 제품명 `wPost`, 파일 버전 `0.2.0`, 제작자 `Hyunwook Park` 확인. 앱의 숫자형 제품 버전은 `0.2.0.0`, ASAR 앱 버전은 `0.2.0`이다.
- ASAR에 JetBrains Mono Regular/Bold와 Noto Sans KR 원본 TTF 3개가 포함됐으며 SHA-256이 소스와 일치한다. 라이선스 4개와 디자인 자산 고지도 소스와 일치한다.
- 앱·설치기는 미서명이며 서명 테이블 크기는 0이다.
- **Windows 실제 설치·업그레이드·제거, 작업표시줄 고정 아이콘 갱신, Windows 화면 배율은 Linux에서 직접 검증하지 않았다.** 앱 내부의 글자 크기 설정과 Windows 배율은 별개다.

## 로컬 재현

Windows x64에서는 `npm ci` 후 `npm run dist:win`을 사용한다. 일반 빌드는 저장소의 PNG/ICO를 사용하며 아이콘을 다시 생성할 때만 `rsvg-convert`와 `npm run icons:build`가 필요하다.

다음은 Node.js 24 이상과 로컬 Docker를 갖춘 Linux의 명령이다.

```bash
npm ci
npm run check
npm run build
mkdir -p release
docker run --rm --platform linux/amd64 \
  --mount "type=bind,src=${PWD},dst=/project,readonly" \
  --mount "type=bind,src=${PWD}/release,dst=/project/release" \
  --workdir /project \
  --entrypoint /bin/bash \
  electronuserland/builder@sha256:41ae540902461b6cbc988987db79547fcc10cda04d2a6c6367504f59d4b37c64 \
  -lc 'node node_modules/electron-builder/out/cli/cli.js --win nsis --x64 --publish never'
sha256sum release/wPost-0.2.0-x64-Setup.exe
```

Windows의 확인 명령:

```powershell
Get-FileHash .\wPost-0.2.0-x64-Setup.exe -Algorithm SHA256
```

체크섬은 이번 생성 파일의 식별자이다. 빌드 도구의 타임스탬프 등으로 재빌드 결과는 달라질 수 있다. 실제 설치 확인은 [배포 절차](../releasing.md)를 따른다.

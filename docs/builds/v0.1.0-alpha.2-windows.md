## 환경과 확인 결과

Rocky Linux 로컬 환경에서 프로덕션 번들을 만들고 아래 Docker 이미지의 Node.js 24.15.0 / Wine 11.0으로 패키징했다. Electron 44.7.0, electron-builder 26.15.3, NSIS 3.0.4.1을 사용했다.

- `npm run check` 통과: TypeScript, Prettier, 단위/통합 테스트 24개.
- 실제 Electron UI 시나리오 2개 통과.
- Linux의 alpha.1 패키지에서 만든 워크스페이스·히스토리·응답이 alpha.2에서 동일하게 복원됨을 확인. 이전 JSON 백업 가져오기와 히스토리 중복 방지도 확인.
- 글꼴 2종 로딩, 앱 아이콘·라이선스 화면, 1000×700 및 1440×940 창 확인.
- 7-Zip NSIS 아카이브 무결성 검사: `Everything is Ok`.
- 내부 `wPost.exe`는 x86-64 PE이며 설치 부트스트랩은 PE32이다.
- 앱과 설치기의 `ProductName`은 `wPost`, `FileVersion`은 `0.1.0-alpha.2`, `CompanyName`은 `Hyunwook Park`이다. 앱 PE의 숫자형 `ProductVersion`은 도구가 생성한 `0.1.0.0`이며 ASAR의 앱 버전은 `0.1.0-alpha.2`이다.
- 앱·설치기 각각의 아이콘 리소스 7개가 원본 ICO의 이미지와 일치한다. 패키지의 글꼴·PNG·라이선스 원문도 소스와 일치한다.
- 코드 서명 없음: 앱·설치기의 서명 테이블 크기는 0이다.
- **실제 Windows 설치·업그레이드·실행·제거는 사용자 검증 예정**이다. Linux의 데이터 호환성 확인이 Windows 설치 검증을 대신하지는 않는다.

## 로컬 재현

Node.js 24 이상, npm, 로컬 Docker를 준비하고 프로젝트 루트에서 실행한다. Windows x64에서는 `npm ci` 후 `npm run dist:win`을 사용한다.

```bash
npm ci
npm run check
npm run build
mkdir -p release
docker run --rm --platform linux/amd64 \
  --mount "type=bind,src=${PWD},dst=/project,readonly" \
  --mount "type=bind,src=${PWD}/release,dst=/project/release" \
  --workdir /project \
  --entrypoint /bin/bash \
  electronuserland/builder@sha256:41ae540902461b6cbc988987db79547fcc10cda04d2a6c6367504f59d4b37c64 \
  -lc 'node node_modules/electron-builder/out/cli/cli.js --win nsis --x64 --publish never'
sha256sum release/wPost-0.1.0-alpha.2-x64-Setup.exe
```

Windows에서 받은 파일은 다음 명령으로 비교한다.

```powershell
Get-FileHash .\wPost-0.1.0-alpha.2-x64-Setup.exe -Algorithm SHA256
```

체크섬은 이번 생성 파일의 식별자이며 빌드 도구 타임스탬프 등으로 재빌드 결과가 달라질 수 있다. 실제 설치 확인 항목은 [배포 절차](../releasing.md)를 따른다.

# 버전 관리와 Windows 로컬 배포

## 버전 올리기

1. 작업 브랜치에서 구현하고 `rules/rules.md`와 `CHANGELOG.md`를 갱신한다.
2. 필요할 때 `npm version 0.2.0 --no-git-tag-version`처럼 버전을 지정한다. 앱, 설치 파일 이름, 백업 메타데이터는 `package.json`을 따른다.
3. `npm run check`, `npm run test:e2e`로 검증한다. Linux의 디스플레이 없는 환경에서는 `xvfb-run -a npm run test:e2e`를 쓴다.
4. Windows x64 로컬 PC에서 `npm ci` 후 `npm run dist:win`을 실행한다.
5. 검증한 변경을 커밋하고 `v0.2.0`처럼 버전 태그를 붙인다. 브랜치와 태그를 원격에 푸시하고 실제 결과를 작업 기록에 남긴다.
6. 검증한 최신 버전 브랜치를 `main`에 병합하고 푸시한다. 다음 버전 브랜치는 최신 `main`에서 시작하며, 이전 릴리스 태그는 유지한다.

릴리스 명령은 현재 버전에 맞게 바꾼다. 기존 태그를 이동하거나 덮어쓰지 않는다. `dist:win`은 원격 게시를 수행하지 않는다.

## Windows 설치 확인

- Windows 10/11 x64에서 NSIS 설치 마법사가 실행되는지 확인한다.
- 설치 경로 선택, 사용자별 설치, 바탕화면·시작 메뉴 바로가기를 확인한다.
- 시작 → 요청 전송 → 저장 → 앱 종료 → 재실행 후 기록 복원을 확인한다.
- 한글 경로에 전체 백업을 저장하고 새 데이터 디렉터리에서 가져온다.
- 바이너리 응답 파일은 원본과 SHA-256을 비교한다.
- 이전 버전 위에 설치해 컬렉션·환경·히스토리가 유지되는지 확인한다. `Wook Post`에서 `wPost`로 이름이 바뀌는 경우, 기존 바로가기가 정리되고 새 주황색 P 아이콘과 이름이 표시되는지도 확인한다. 앱 정보의 저장 위치는 계속 `%APPDATA%/Wook Post`여야 한다.
- 제거 후 실행 파일·바로가기를 확인한다. 사용자 데이터의 유지 여부도 기록한다. 데이터 삭제는 별도로 명확하게 선택해야 한다.
- 인터넷 없는 상태에서 앱 실행·로컬 API 호출·파일 가져오기/내보내기를 확인한다. 영문 JetBrains Mono와 한글 Noto Sans KR가 외부 다운로드 없이 표시되는지 확인한다.
- 100%·125%·150% Windows 배율에서 URL·본문·환경 설정·내보내기 화면을 확인한다. 최소 창 크기는 1000×700이다.
- 앱 설정에서 글꼴·글자 크기 80%·125%·150%를 적용하고 취소·저장·재실행을 확인한다. 이는 Windows 화면 배율과 별개다.
- 컬렉션 이름 변경, 삭제 시 요청 보존/함께 삭제, 열린 미저장 탭·히스토리 보존을 확인한다.
- 큰 정수 `9007199254740993`이 정렬·전송·응답 복사에서도 바뀌지 않는지 확인한다.

## 설치 파일과 서명

생성 경로: `release/<version>/wPost-<version>-x64-Setup.exe`.

`package.json`의 버전으로 폴더를 나누며 다른 버전 산출물은 유지한다. 같은 버전의 재빌드는 해당 폴더를 갱신한다. `npm run dist:win`은 설치 파일 옆에 `.exe.sha256` 체크섬도 생성한다. 설치 파일과 빌드 중간 산출물은 Git에 포함하지 않으며, 폴더 사용법은 [`release/README.md`](../release/README.md)에 기록한다.

`0.2.0`의 Windows x64 설치 파일은 로컬 Docker에서 생성했다. [파일 크기·체크섬·재현 명령](builds/v0.2.0-windows.md)을 기록해 두었다. 이 패키징 확인은 실제 Windows 설치 검증을 대신하지 않는다.

현재 인증서와 배포 서명은 구성하지 않았다. 공개 배포 전에 코드 서명과 설치 검증을 완료한다. 제작자 이름과 이메일 메타데이터는 코드 서명을 대신하지 않는다.

빌드 PC에는 Node.js 24 LTS 이상과 npm이 필요하다. 최초 의존성 설치와 패키징 도구 다운로드에는 네트워크가 필요할 수 있다. 설치된 앱 사용에는 Node.js 설치가 필요 없다.

설치 업그레이드 호환성을 위해 `appId: com.parkhw328.wookpost`는 유지한다. 이름과 디자인의 기준은 [브랜딩 문서](branding.md)를 따른다.

## 의존성 확인 기록

2026-10-08 기준 `npm audit --omit=dev`는 0건이다. 전체 `npm audit`는 electron-builder 도구 의존성의 `sprintf-js` 서비스 거부 경고에서 파생된 moderate 8건을 보고했다. 강제 다운그레이드는 적용하지 않았으며, 빌드 도구 업데이트 시 다시 확인한다. 런타임 의존성은 `zod`이고 React와 아이콘 코드는 빌드 시 화면 번들에 포함한다.

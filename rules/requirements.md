# wPost 요구사항

사용자가 요청한 제품 기능과 작업·배포 방식을 누적 관리한다. 최초 정리일은 2026-10-31이며, 초기 요구사항 원문과 기존 작업 기록·변경 이력을 근거로 작성했다. 각 항목의 적용 내용은 구현 기록을 요약한 것으로, 사용자 요청 원문과 구분한다.

새 작업은 [작업 규칙](rules.md), 이 문서 순서로 먼저 읽는다. 같은 주제의 요청이 바뀌면 최신 사용자 지시를 적용하고 이전 요청과 변경 이유를 남긴다. 새 요구사항은 날짜·출처·적용 기준과 함께 추가하며, 구현·검증 결과는 `rules.md`와 [변경 이력](../CHANGELOG.md)에 기록한다.

초기 원문은 Git 추적에서 제외된 `resources/setting.txt`이며, 로컬 파일이 없는 환경에서도 다음 Git 이력으로 확인할 수 있다. 이 문서는 새 체크아웃에서도 읽을 수 있는 요구사항 기준이다.

```bash
git show 1d80829:resources/setting.txt
```

## 2026-10-08 · 초기 제품·작업 요구사항

출처: 위 초기 원문의 `rules`와 `requirements`, [첫 구현 기록](rules.md#2026-10-08--010-alpha1-구현), [제품 조사와 구현 방향](../docs/benchmark.md).

- **REQ-001 · API 클라이언트와 성능 목표**: Postman 무료 버전과 유사 애플리케이션을 분석·벤치마킹해 AJAX/API 통신용 프로그램을 만든다. 경쟁 제품을 뛰어넘는 성능을 목표로 한다. Postman·Bruno·Hoppscotch·Insomnia 기능 조사를 반영했으며, 경쟁 제품 대비 성능 우위는 아직 측정하지 않은 목표다.
- **REQ-002 · 직관적인 UI/UX**: 요청 작성·전송·결과 확인·재사용 흐름을 사용자가 쉽게 이해하도록 구성한다. 현재 적용 기준은 한국어 UI, 여러 요청 탭, 컬렉션·검색·환경 변수, 단축키와 명확한 응답 상태·시간·크기 표시다.
- **REQ-003 · 결과 가져오기·내보내기**: 요청 결과를 확실하게 저장하고 다시 가져올 수 있어야 한다. 현재는 단일 요청·응답 JSON, 전체 백업, 응답 원본 바이트 저장을 제공한다. 원본 본문 파일 저장과 앱에서 복원 가능한 JSON 백업은 구분한다.
- **REQ-004 · 로컬 히스토리와 이동성**: 히스토리를 로컬에 보관하고 가져오기·내보내기를 제공한다. 현재는 SQLite에 기록을 유지하며 자동 삭제하지 않고, 재실행·재열기·백업 복원을 지원한다.
- **REQ-005 · Windows 설치형·로컬 빌드·제작자**: 기본 대상은 Windows 64비트이며 InstallShield 형태의 설치 마법사를 제공한다. 빌드는 로컬에서 수행하고 제작자를 **Hyunwook Park (parkhw328@gmail.com)**으로 표시한다. 실제 구현은 설치 경로를 선택하는 NSIS 마법사이며 상용 InstallShield 프로젝트는 아니다. 후속 요청에 따라 개발 환경의 로컬 Docker에서도 Windows 설치 파일을 생성했고, 실제 Windows 검증은 사용자가 진행하기로 기록했다.
- **REQ-006 · 작업 기록과 버전 관리**: 작업한 내용을 `rules/rules.md`에 정리하면서 진행하고, 커밋·푸시와 함께 버전을 관리한다. 현재 버전 운영 방식은 REQ-018을 따르며 변경·검증·남은 일은 작업 기록과 `CHANGELOG.md`에 남긴다.

## 기존 요구사항을 뒷받침하는 구현·호환성 기준

아래는 사용자 요청을 구현하면서 정한 현재 동작과 호환성 기준이다. 상세 사용법·한도는 [사용 안내](../docs/usage.md), 식별자·브랜드 호환성은 [브랜딩 문서](../docs/branding.md)를 따른다.

- HTTP 메서드, 쿼리·헤더, JSON·텍스트·URL 인코딩 폼, Bearer/Basic 인증, 환경 변수, 취소·타임아웃·리다이렉트 설정을 유지한다. 응답 JSON 정렬은 큰 정수·소수 표기·중복 키를 보존한다.
- 백업은 가져오기 미리보기, 기존 데이터에 추가, 실패 시 전체 롤백, 동일 히스토리 중복 방지를 제공한다. Postman Collection v2.0/v2.1 가져오기와 v2.1 내보내기를 지원하며 지원하지 않는 항목은 알린다.
- 설치 식별자 `com.parkhw328.wookpost`, Windows 저장 위치 `%APPDATA%/Wook Post/wook-post.sqlite`, 백업 `format: wook-post`와 `schemaVersion: 1`, SQLite `user_version: 1`을 현재 호환성 기준으로 유지한다. 변경이 필요하면 데이터 이전·이전 백업 호환성 검증을 함께 다룬다.
- 화면 설정은 기존 DB의 별도 `appearance` 테이블에 저장하고 PC별 설정이므로 요청·히스토리 백업에 포함하지 않는다.
- 파일 전송은 메인 프로세스에서 수행하고 multipart boundary·전송 길이를 자동 생성한다. 현재 한도는 파일·폼 값 합계 100 MiB, 텍스트 1 MiB, 요청당 파일 100개다. 경로·파일 크기 오류를 전송 전에 알리고 이전 DB·백업 요청에는 새 필드 기본값을 적용한다.
- 계정·클라우드 동기화·자동 업로드 없이 로컬 데이터를 사용하고 지정한 API 서버로 요청을 보낸다. 로컬 저장소와 백업의 민감 값은 현재 평문이며, 암호화가 구현된 것으로 설명하지 않는다.

## 남아 있는 검증과 후속 후보

- **REQ-001의 성능 목표**: 경쟁 제품과 같은 Windows PC·서버·요청 조건에서 시작 시간·메모리·요청 오버헤드 등을 비교해야 한다. [측정 계획](../docs/benchmark.md)의 목표 수치는 실측 결과가 아니다.
- **REQ-005의 실제 Windows 확인**: 설치기 생성·아카이브·버전·아이콘·라이선스 검사는 기록돼 있으나, 실제 설치·업그레이드·제거·Windows 배율별 동작은 최신 기록에서 미검증 상태다. 사용자의 실제 확인 결과를 받으면 기록을 갱신한다. 코드 서명도 현재 미적용이다.
- **확정 요청과 구분할 후보**: 기존 작업 기록에 있는 cURL/OpenAPI 가져오기, 프록시·클라이언트 인증서, 쿠키 관리, OAuth 2.0, 테스트 스크립트·컬렉션 실행기, 민감 값 암호화, 대용량 백업 스트리밍, 응답 비교는 후속 후보이며 완료 기능이나 새로 승인된 작업으로 취급하지 않는다. 초기 후보였던 파일 업로드는 REQ-023으로 요청되어 구현됐다.
